# Experiment 04. 규칙 기반 명령어 분석기 개선 및 성능 평가

## 1. 연구 주제

한국어 음성 명령의 의도 분류 및 실행 대상 추출 정확도 향상을 위한 규칙 기반 명령어 분석기 개선

## 2. 연구 배경

VoicePilot은 사용자의 음성을 인식하고, 인식된 문장을 분석하여 컴퓨터를 제어하는 음성 기반 인터페이스이다.

전체 시스템은 다음과 같은 처리 과정을 가진다.

음성 입력 → 음성 인식(ASR) → 오류 보정 → 명령어 분석 → 명령 실행

실험 1에서는 Whisper 모델별 음성 인식 성능을 비교하였으며, 실험 2에서는 Initial Prompt를 활용하여 음성 인식 정확도를 개선하였다. 실험 3에서는 한글 자모 기반 편집 거리를 활용한 오류 보정 방법을 연구하였다.

그러나 음성 인식 정확도가 향상되더라도 명령어 분석기가 사용자의 의도를 정확하게 파악하지 못하면 실제 시스템의 명령 처리 성능은 제한된다.

특히 기존 분석기에서는 부정 명령을 실행 명령으로 판단하거나, 검색어 및 파일명을 추출하는 과정에서 필요한 단어를 삭제하는 문제가 발견되었다.

이에 본 실험에서는 명령어 분석기의 구조를 개선하고, 기존 분석기와 개선된 분석기의 성능을 정량적으로 비교하였다.

## 3. 연구 목적

- 한국어 명령 표현의 다양성에 대응한다.
- 명령 유형 분류 정확도를 향상한다.
- 검색어, 파일명, 폴더명 등의 실행 정보를 정확하게 추출한다.
- 부정 명령과 불완전한 명령의 잘못된 실행 판단을 감소시킨다.
- 기존 기능을 유지하면서 분석기의 성능을 개선한다.
- 새로운 텍스트 명령을 활용하여 개선된 분석기의 일반화 가능성을 평가한다.

## 4. 연구 가설

H1. 문장 전체의 구조를 고려한 정규표현식 기반 분석은 단순 키워드 중심 분석보다 명령 유형 분류 정확도가 높을 것이다.

H2. 명령어와 실행 대상의 분리 추출은 전체 명령 일치율을 향상할 것이다.

H3. 부정 표현 검사와 실행 대상 유효성 검사는 잘못된 실행 판단을 감소시킬 것이다.

H4. 문장부호와 띄어쓰기 변형에 대한 처리는 음성 인식 결과에 대한 분석기의 강건성을 향상할 것이다.

## 5. 이론적 배경

### 5.1 자연어 이해(Natural Language Understanding)

자연어 이해는 사용자가 입력한 자연어 문장에서 의미와 의도를 파악하는 과정이다.

VoicePilot에서는 자연어 이해 과정을 의도 분류와 실행 정보 추출의 두 단계로 구성하였다.

### 5.2 의도 분류(Intent Classification)

의도 분류는 사용자의 발화가 어떤 목적을 가지는지 판단하는 과정이다.

본 시스템에서는 다음 네 가지 유형을 정의하였다.

| 명령 유형  | 의미                                       |
| ---------- | ------------------------------------------ |
| open_app   | 프로그램 실행                              |
| web_search | 웹 검색                                    |
| open_file  | 파일 열기                                  |
| unknown    | 실행할 수 없거나 실행하지 않아야 하는 발화 |

### 5.3 슬롯 추출(Slot Filling)

슬롯 추출은 명령을 실행하는 데 필요한 구체적인 정보를 자연어 문장에서 추출하는 과정이다.

| 명령 유형  | 추출 정보    |
| ---------- | ------------ |
| open_app   | target       |
| web_search | query        |
| open_file  | name, folder |
| unknown    | 없음         |

예를 들어 "바탕화면에 있는 보고서 파일 열어줘"라는 문장에서 다음과 같은 정보를 추출한다.

- 명령 유형: open_file
- 파일명: 보고서
- 폴더: desktop

명령 유형이 정확하더라도 슬롯 추출 결과가 잘못되면 사용자가 원하는 작업을 수행하기 어렵다.

### 5.4 규칙 기반 자연어 분석

규칙 기반 분석은 사전에 정의한 문자열 패턴과 문법 규칙을 활용하여 자연어를 처리하는 방식이다.

본 프로젝트에서는 지원하는 명령 유형이 제한적이고, 분석 결과의 설명 가능성과 실행 안정성이 중요하므로 정규표현식을 활용한 규칙 기반 방식을 선택하였다.

장점은 다음과 같다.

- 별도의 모델 학습이 필요하지 않다.
- 명령 판단 근거를 확인하기 쉽다.
- 제한된 명령 영역에서 효율적으로 사용할 수 있다.
- 실행 허용 조건을 명시적으로 설정할 수 있다.

반면 사전에 정의하지 않은 표현이나 복잡한 자연어 문장을 처리하는 데 한계가 있다.

### 5.5 정규표현식의 부분 일치와 전체 일치

Python의 re.search()는 문자열 내부에서 패턴과 일치하는 부분을 탐색한다.

반면 re.fullmatch()는 문자열 전체가 지정된 패턴과 일치하는지 검사한다.

기존 분석기에서는 부분 일치 중심의 규칙으로 인해 실행 의도가 없는 문장도 실행 명령으로 판단하는 문제가 발생하였다.

개선된 분석기에서는 전체 일치를 활용하여 명령 판단 조건을 강화하였다.

## 6. 기존 분석기(V1)의 문제점

기존 분석기의 문제점을 확인하기 위해 실험 3의 실패 사례와 추가 진단 문장을 분석하였다.

| 입력 문장                                   | 기존 문제점                      |
| ------------------------------------------- | -------------------------------- |
| 나 계산기 쓰고 싶어                         | 간접적인 실행 요청 미인식        |
| 인터넷 좀 하고 싶어                         | 다양한 요청 표현 미지원          |
| 계산기 켜지 마                              | 부정 명령을 실행 명령으로 판단   |
| 계산기 실행 방법 검색해 줘                  | 웹 검색을 프로그램 실행으로 판단 |
| 내일 서울 날씨 알아봐줘                     | 검색어에 불필요한 표현 포함      |
| 바탕화면에 있는 테스트 파일을 찾아서 열어줘 | 파일명 추출 오류                 |
| 바탕화면 있는 사진 열어줘                   | 폴더 추출 오류                   |
| 열어줘                                      | 빈 파일명을 실행 대상으로 반환   |
| 검색해줘                                    | 빈 검색어를 실행 대상으로 반환   |

기존 분석기의 주요 문제는 다음과 같이 분류하였다.

1. 명령 표현의 다양성 부족
2. 부정 표현 처리 미흡
3. 명령 유형 간 충돌
4. 실행 정보 추출 과정의 문자열 손상
5. 불완전한 명령에 대한 유효성 검사 부족

비교 실험의 재현성을 확보하기 위해 기존 분석기를 experiments/baselines/command_parser_v1.py에 별도로 보존하였다.

## 7. 개선된 분석기(V2) 설계

개선된 분석기는 다음 순서로 동작한다.

1. 입력 문장 정규화
2. 빈 입력 및 부정 명령 검사
3. 프로그램 실행 명령 분석
4. 파일 열기 명령 분석
5. 웹 검색 명령 분석
6. 해당하는 명령이 없으면 unknown 반환

기존 제어 모듈과의 호환성을 유지하기 위해 명령어 반환 형식은 변경하지 않았다.

## 8. 문장 정규화 개선

음성 인식 결과에는 불필요한 공백과 문장부호가 포함될 수 있다.

이를 처리하기 위해 다음 정규화 과정을 적용하였다.

- 문장 양끝의 공백 제거
- 연속된 공백을 하나의 공백으로 통합
- 문장 끝의 불필요한 문장부호 제거

파일 확장자나 검색어에 포함된 문장부호가 손상되지 않도록 문장 내부의 기호는 일괄 삭제하지 않았다.

문장 정규화 기능은 7개 테스트에서 모두 기대한 결과를 반환하였다.

## 9. 부정 명령 처리

기존 분석기에서는 프로그램명과 실행 관련 단어가 포함되어 있으면 부정 표현이 존재하더라도 실행 명령으로 판단할 수 있었다.

이를 개선하기 위해 명령 분석 이전에 부정 표현을 검사하도록 구성하였다.

주요 검사 표현은 다음과 같다.

- 하지 마
- 하지 마세요
- 하지 말아 줘
- 하지 말아 주세요
- 필요 없어
- 하지 않았으면 좋겠어

부정 명령으로 판단되면 unknown을 반환하고 이후 명령 분석을 진행하지 않는다.

7개의 부정 명령 테스트에서 모두 실행 판단을 차단하였다.

다만 규칙에 포함되지 않은 부정 표현이나 복합 문장까지 완전하게 처리할 수 있는 것은 아니다.

## 10. 프로그램 실행 분석 개선

### 10.1 문장 전체 일치 적용

프로그램 실행 분석에 re.fullmatch()를 적용하였다.

프로그램명과 실행 관련 단어가 포함되어 있더라도 문장 전체가 실행 요청 구조와 일치하지 않으면 프로그램 실행 명령으로 판단하지 않는다.

이를 통해 프로그램 실행 방법을 검색하는 문장이 프로그램 실행 명령으로 잘못 분류되는 문제를 개선하였다.

### 10.2 다양한 요청 표현 지원

다음과 같은 표현을 처리하도록 규칙을 확장하였다.

- 실행해 줘
- 켜 줘
- 열어 줘
- 띄워 줄래
- 시작해 봐
- 실행 부탁해
- 쓰고 싶어
- 사용하고 싶어요

또한 목적격 조사와 일부 보조 표현을 허용하였다.

### 10.3 음성 인식 결과의 변형 처리

1차 성능 비교 이후 음성 인식 결과에 포함된 쉼표와 띄어쓰기로 인해 일부 명령이 처리되지 않는 문제를 발견하였다.

이에 다음 기능을 추가하였다.

- 프로그램 실행 분석 단계에서 쉼표를 공백으로 변환
- 실행 해줘와 같은 띄어쓰기 변형 허용
- 열어주와 같은 요청 표현 허용

검색어와 파일명의 손상을 방지하기 위해 쉼표 처리는 프로그램 실행 분석 함수 내부에서만 수행하였다.

추가 개선 이후 9개의 관련 테스트를 모두 통과하였다.

## 11. 웹 검색 분석 개선

기존 분석기는 문장에 포함된 검색 관련 단어를 제거하는 방식으로 검색어를 추출하였다.

이 방식은 검색어 자체에 검색이라는 단어가 포함된 경우 필요한 정보까지 삭제하는 문제가 있었다.

개선된 분석기에서는 문장 끝의 검색 요청 표현을 기준으로 검색어와 요청 부분을 분리하였다.

지원하는 주요 표현은 다음과 같다.

- 검색해 줘
- 검색해 주세요
- 찾아줘
- 찾아봐
- 알아봐 줘
- 검색해 줄래

또한 구글에서, 네이버에서와 같은 문장 시작 부분의 검색 서비스 지정 표현을 제거하였다.

검색어가 비어 있는 경우에는 unknown을 반환하도록 개선하였다.

웹 검색 관련 11개 테스트에서 모두 기대한 결과를 반환하였다.

## 12. 파일 열기 분석 개선

### 12.1 파일명 보존

기존 분석기는 문장 내부의 파일, 문서 등의 단어를 일괄적으로 제거하였다.

이에 따라 실제 파일명에 해당 단어가 포함되어 있으면 파일명이 손상될 수 있었다.

개선된 분석기에서는 파일 열기 요청을 문장 끝에서 분리하고, 파일명 뒤에 붙은 일반적인 요청 표현만 제거하도록 변경하였다.

### 12.2 폴더명 추출

폴더 별칭을 정의하여 다음과 같은 표현을 처리하였다.

| 사용자 표현 | 내부 폴더 값 |
| ----------- | ------------ |
| 바탕화면    | desktop      |
| 데스크톱    | desktop      |
| 내 바탕화면 | desktop      |
| 문서        | documents    |
| 내 문서     | documents    |
| 다운로드    | downloads    |

긴 폴더명을 먼저 검사하여 여러 단어로 구성된 폴더 표현을 처리하도록 설계하였다.

### 12.3 복합 요청 처리

파일을 찾아서 열어줘와 같은 표현을 지원하도록 개선하였다.

### 12.4 빈 파일명 차단

파일명이 추출되지 않으면 unknown을 반환하도록 변경하였다.

파일 열기 관련 13개 테스트에서 모두 기대한 결과를 반환하였다.

## 13. 회귀 테스트

회귀 테스트(Regression Test)는 코드 변경 이후 기존 기능이 정상적으로 유지되는지 확인하는 테스트이다.

기존 test_parser.py에 정의된 32개의 테스트를 사용하였다.

1차 개선 이후와 추가 개선 이후 모두 32개 테스트를 통과하였다.

| 평가 항목      | 결과 |
| -------------- | ---- |
| 전체 테스트 수 | 32   |
| 통과           | 32   |
| 실패           | 0    |
| 통과율         | 100% |

이를 통해 기존 테스트에서 확인된 기능이 개선 이후에도 유지됨을 확인하였다.

다만 기존 테스트의 통과가 모든 가능한 명령에서의 정상 동작을 보장하는 것은 아니다.

- 입력 데이터: results/model_experiment_prompt.csv
- 정답 데이터: dataset/command_labels.csv
- 음성 인식 모델: base, small

## 15. 평가 지표

### 15.1 명령 유형 정확도

명령 유형을 정확하게 분류한 데이터의 비율이다.

명령 유형 정확도 = 유형 일치 수 / 전체 데이터 수 × 100

### 15.2 전체 명령 일치율

명령 유형과 해당 유형의 모든 슬롯이 정답과 일치한 데이터의 비율이다.

전체 명령 일치율 = 유형 및 슬롯 일치 수 / 전체 데이터 수 × 100

### 15.3 잘못된 실행 판단

정답 유형이 unknown인 데이터에서 분석기가 실행 가능한 명령 유형을 반환한 횟수이다.

이는 실제 프로그램 실행 여부가 아닌 분석기의 실행 판단 오류를 의미한다.

### 15.4 문자열 비교 기준

실험 A에서는 이전 실험과의 비교 가능성을 유지하기 위해 공백과 일부 문장부호를 제거하고 영문 대소문자를 통일한 후 슬롯을 비교하였다.

실험 B에서는 파일명과 검색어의 정확한 추출 여부를 확인하기 위해 문자열 양끝의 공백만 제거한 후 비교하였다.

따라서 두 실험의 정확도를 동일한 조건의 결과로 직접 비교하지 않는다.

## 20. 연구의 의의

본 실험은 음성 인식 모델의 성능뿐만 아니라 음성 인식 이후의 자연어 분석 과정이 전체 음성 인터페이스 성능에 중요한 영향을 미친다는 점을 확인하였다.

별도의 대규모 언어 모델이나 추가 학습 과정 없이 규칙 기반 분석기를 개선하여 두 음성 인식 모델에서 전체 명령 일치율을 각각 20.00%p 향상하였다.

또한 새로운 텍스트 명령에 대한 검증에서도 기존 분석기보다 높은 정확도를 확인하였다.

실행하지 않아야 하는 명령에 대한 판단 오류가 감소했다는 점에서 정확도뿐만 아니라 실행 안정성 측면의 개선 가능성도 확인하였다.

## 21. 연구의 한계

1. 기존 음성 데이터가 분석기 개선 과정에 활용되었으므로 해당 데이터의 성능은 독립적인 일반화 성능으로 볼 수 없다.

2. 새로운 텍스트 검증 데이터도 분석기 구조를 알고 있는 상태에서 제작되었으므로 완전히 독립적인 검증 데이터는 아니다.

3. 음성 인식 데이터의 규모가 작고 발화자 다양성이 부족하다.

4. 규칙 기반 분석은 사전에 정의되지 않은 표현이나 복잡한 문장 구조에 대응하기 어렵다.

5. 한국어 목적격 조사와 실제 파일명을 구분하는 데 한계가 있다.

6. 일부 음성 인식 오류와 무음 환각이 해결되지 않았다.

7. 실험 A의 문자열 정규화 방식은 의미 있는 공백이나 문장부호 차이를 평가에서 누락할 수 있다.

8. 실제 프로그램 실행 결과가 아닌 분석기의 반환값을 평가하였다.

9. 분석기 자체의 처리 시간 및 CPU, 메모리 사용량은 별도로 측정하지 않았다.

10. 제한된 검증 데이터에서 잘못된 실행 판단이 0건이었다는 결과가 모든 상황에서의 안전성을 보장하지는 않는다.

본 실험에서는 기존 규칙 기반 명령어 분석기의 문제점을 분석하고 문장 정규화, 부정 표현 처리, 전체 문장 일치, 실행 정보 추출 및 요청 표현 규칙을 개선하였다.

기존 음성 인식 결과를 활용한 비교 실험에서 자모 보정 0.9 조건의 전체 명령 일치율은 base 모델에서 66.67%에서 86.67%로, small 모델에서 73.33%에서 93.33%로 향상되었다.

새로운 텍스트 명령 40개를 활용한 검증에서는 명령 유형 정확도 100%, 전체 명령 일치율 97.50%를 달성하였다.

또한 실행하지 않아야 하는 10개 검증 문장에서 잘못된 실행 판단이 발생하지 않았다.

이러한 결과를 통해 제한된 명령 영역에서 규칙 기반 자연어 분석기의 개선이 음성 인터페이스의 명령 처리 정확도와 실행 안정성을 향상하는 데 기여할 수 있음을 확인하였다.

향후 음성 활동 감지와 실행 안전성 연구를 통해 남아 있는 무음 환각 및 잘못된 실행 판단 문제를 개선하고자 한다.
