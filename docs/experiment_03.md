# Experiment 03. 한글 자모 기반 음성 인식 오류 보정

## 1. 연구 배경

VoicePilot은 사용자의 한국어 음성 명령을 인식하고, 이를 분석하여 PC를 제어하는 음성 비서 시스템이다.

실험 1에서는 Whisper 모델별 음성 인식 성능을 비교하였으며, 실험 2에서는 initial_prompt를 활용하여 음성 인식 정확도를 개선하였다.

그러나 프롬프트를 적용한 이후에도 발음이 유사한 단어를 잘못 인식하는 문제가 발생하였다.

대표적인 사례는 다음과 같다.

| 실제 발화  | 음성 인식 결과 |
| ---------- | -------------- |
| 인공지능   | 인공지는       |
| 파이썬     | 파이선         |
| 숭실대학교 | 송실대학교     |
| 계산기     | 개상지         |
| 메모장     | 메모짱         |

이러한 오류는 음성 인식 모델의 크기를 증가시키는 방법으로 일부 해결할 수 있지만, 처리 시간과 컴퓨팅 자원 사용량이 증가할 수 있다.

따라서 본 실험에서는 음성 인식 결과에 별도의 문자열 보정 알고리즘을 적용하여 인식 성능을 개선할 수 있는지 확인하고자 한다.

## 2. 연구 목적

본 실험의 목적은 다음과 같다.

1. 일반 문자 기반 문자열 유사도와 한글 자모 기반 문자열 유사도를 비교한다.
2. Levenshtein Distance를 활용한 음성 인식 오류 보정 알고리즘을 구현한다.
3. 유사도 임계값에 따른 보정 성능의 차이를 분석한다.
4. 정상적으로 인식된 단어가 잘못 보정되는 과잉 보정 문제를 분석한다.
5. 음성 인식 오류 보정이 실제 명령어 분석 정확도에 미치는 영향을 확인한다.

## 3. 연구 가설

- H1. 한글 자모 기반 유사도는 일반 문자 기반 유사도보다 한국어의 부분적인 문자 오류를 세밀하게 반영할 수 있을 것이다.
- H2. 자모 기반 오류 보정을 적용하면 음성 인식 정확도가 향상될 것이다.
- H3. 유사도 임계값이 낮을수록 보정 대상이 증가하지만 과잉 보정의 가능성도 증가할 것이다.
- H4. 음성 인식 오류 보정은 명령어 분석 정확도 향상에 기여할 것이다.

## 4. 이론적 배경

### 4.1 Levenshtein Distance

Levenshtein Distance는 두 문자열을 동일하게 만들기 위해 필요한 최소 편집 연산 횟수를 의미한다.

편집 연산은 다음 세 가지로 구성된다.

- 삽입(Insertion)
- 삭제(Deletion)
- 치환(Substitution)

본 실험에서는 동적 계획법(Dynamic Programming)을 활용하여 편집 거리를 계산하였다.

두 문자열의 길이가 각각 m, n일 때 구현한 알고리즘의 시간 복잡도와 공간 복잡도는 모두 O(mn)이다.

### 4.2 문자열 유사도

문자열의 길이에 따른 편집 거리의 차이를 보완하기 위해 다음과 같이 정규화된 유사도를 계산하였다.

Similarity(A, B) = 1 - Distance(A, B) / max(len(A), len(B))

유사도는 0에서 1 사이의 값을 가지며, 1에 가까울수록 두 문자열이 유사하다는 것을 의미한다.

두 문자열이 모두 빈 문자열인 경우에는 유사도를 1로 정의하였다.

### 4.3 한글 자모 분리

한글은 초성, 중성, 종성의 조합으로 구성된다.

일반 문자 기반 비교에서는 완성형 한글 한 글자를 하나의 문자로 처리한다. 따라서 일부 자모만 다른 경우에도 해당 글자 전체가 다른 것으로 계산된다.

본 실험에서는 Python의 unicodedata.normalize("NFD", text)를 사용하여 한글을 자모 단위로 분리하였다.

이를 통해 완성형 문자 내부의 부분적인 차이를 편집 거리에 반영할 수 있도록 하였다.

단, 자모 기반 유사도는 문자 구조의 유사도를 측정하는 방식이며, 실제 음성학적 발음 유사도를 직접 계산하는 방식은 아니다.

## 5. 일반 문자 기반 유사도와 자모 기반 유사도 비교

| 비교 단어           | 일반 문자 유사도 | 자모 유사도 |
| ------------------- | ---------------: | ----------: |
| 계산기 / 개상지     |            0.00% |      57.14% |
| 메모장 / 메모짱     |           66.67% |      85.71% |
| 파이썬 / 파이선     |           66.67% |      85.71% |
| 인공지능 / 인공지는 |           75.00% |      90.91% |
| 크롬 / 그럼         |            0.00% |      60.00% |
| 계산기 / 세탁기     |           33.33% |      42.86% |
| 계산기 / 계산기     |          100.00% |     100.00% |

일반 문자 기반 비교에서는 계산기와 개상지의 모든 글자가 다르므로 유사도가 0%로 계산되었다.

반면 자모 기반 비교에서는 일부 자모가 일치하여 57.14%의 유사도가 나타났다.

메모장과 메모짱, 파이썬과 파이선에서도 자모 기반 비교가 부분적인 문자 차이를 더욱 세밀하게 반영하였다.

그러나 크롬과 그럼처럼 의미가 서로 다른 단어도 높은 유사도를 가질 수 있다는 문제를 확인하였다.

따라서 문자열 유사도가 높다는 사실만으로 해당 단어가 잘못 인식되었다고 판단할 수는 없다.

## 6. 오류 보정 알고리즘 구현

오류 보정 알고리즘은 speech/error_correction.py에 구현하였다.

### 6.1 주요 함수

| 함수               | 역할                        |
| ------------------ | --------------------------- |
| decompose_hangul() | 한글 자모 분리              |
| edit_distance()    | 최소 편집 거리 계산         |
| similarity()       | 정규화된 문자열 유사도 계산 |
| correct_word()     | 어휘 사전 기반 단어 보정    |
| correct_text()     | 문장 단위 오류 보정         |

### 6.2 알고리즘 처리 과정

1. 음성 인식 결과를 입력받는다.
2. 공백을 기준으로 문장을 단어 단위로 분리한다.
3. 각 단어와 어휘 사전의 후보 단어 사이의 유사도를 계산한다.
4. 가장 높은 유사도를 가진 후보 단어를 선택한다.
5. 유사도가 설정된 임계값 이상이면 해당 후보 단어로 변경한다.
6. 임계값 미만이면 기존 단어를 유지한다.
7. 처리된 단어를 다시 하나의 문장으로 결합한다.

### 6.3 보정용 어휘 사전

VoicePilot에서 사용되는 주요 프로그램명, 폴더명 및 일부 검색 관련 어휘를 선정하였다.

```python
VOCABULARY = [
    "계산기", "크롬", "메모장",
    "파일 탐색기", "바탕화면",
    "다운로드", "문서",
    "파이썬", "인공지능"
]
```

일반 문자 기반 보정과 자모 기반 보정에 동일한 어휘 사전을 적용하였다.

현재 구현은 공백 단위로 문자열을 분리하기 때문에 여러 단어로 구성된 어휘를 효과적으로 처리하기 어렵다는 한계가 있다.

## 9. 평가 지표

### 9.1 완전 일치율

정규화된 음성 인식 결과가 정답 문장과 완전히 일치하는 비율이다.

완전 일치율 = 완전 일치 문장 수 / 전체 유음 발화 수 × 100

### 9.2 문자 오류율(CER)

Character Error Rate는 정답 문자열에 대한 문자 편집 오류의 비율을 의미한다.

CER = 전체 편집 거리의 합 / 전체 정답 문자 수 × 100

띄어쓰기와 문장부호의 영향을 줄이기 위해 정답 및 인식 결과를 정규화한 후 계산하였다.

무음 데이터는 완전 일치율과 CER 계산에서 제외하였다.

### 9.3 개선 및 악화 건수

- 개선: 보정 이후 정답과의 편집 거리가 감소한 경우
- 악화: 보정 이후 정답과의 편집 거리가 증가한 경우
- 과잉 보정: 기존 인식 결과가 정답과 일치하였으나 보정 이후 불일치하게 된 경우

과잉 보정은 악화 사례에 포함되는 세부 지표이다.

### 9.4 명령어 분석 성능

음성 인식 결과를 기존 명령어 분석기에 입력하여 다음 지표를 측정하였다.

- 명령 유형 정확도
- 전체 명령 일치율
- 잘못된 실행 판단 건수

전체 명령 일치율은 명령 유형뿐만 아니라 프로그램명, 검색어, 파일명 및 폴더 정보가 정답과 일치하는지를 평가한다.

명령어 분석 평가에는 무음 데이터를 포함한 전체 30개 데이터를 사용하였다.

## 11. 임계값에 따른 성능 분석

낮은 임계값에서는 보정 가능한 단어가 증가하였으나, 정상적으로 인식된 단어까지 변경되는 문제가 발생하였다.

특히 small 모델에 자모 기반 보정과 임계값 0.5를 적용한 경우 완전 일치율이 93.10%에서 75.86%로 감소하였다.

이는 기존 음성 인식 성능이 높은 모델에 공격적인 오류 보정을 적용할 경우 오히려 전체 성능이 저하될 수 있음을 보여준다.

반면 임계값 0.9에서는 두 모델 모두 과잉 보정 없이 한 문장의 오류를 개선하였다.

따라서 오류 보정에서는 보정 가능한 단어의 수를 증가시키는 것뿐만 아니라 정상적으로 인식된 단어를 유지하는 것도 중요하다.

파이선, 차용법, 찾아줘

파이썬 차용법, 찾아줘

파이선은 파이썬으로 보정되었지만 차용법은 사용법으로 보정되지 않았다.

이는 어휘 사전에 포함된 단어를 중심으로 보정하는 현재 알고리즘의 한계를 보여준다.

### 12.3 과잉 보정

| 보정 전                            | 보정 후                          |
| ---------------------------------- | -------------------------------- |
| 바탕화면에 있는 사진 열어줘        | 바탕화면 있는 사진 열어줘        |
| 메모장이 어디 있더라               | 메모장 어디 있더라               |
| 인공지능이 미래 사회에 미치는 영향 | 인공지능 미래 사회에 미치는 영향 |

현재 알고리즘은 조사와 명사를 별도로 구분하지 않고 공백 단위의 문자열 전체를 비교한다.

따라서 정상적으로 인식된 명사와 조사의 결합 형태를 어휘 사전에 등록된 명사로 변경하면서 조사가 삭제되는 문제가 발생하였다.

### 12.4 의미가 다른 단어의 보정

임계값 0.6을 적용한 개별 테스트에서 다음과 같은 결과를 확인하였다.

| 입력             | 보정 결과        |
| ---------------- | ---------------- |
| 그럼 실행해줘    | 크롬 실행해줘    |
| 그럼 내일 만나자 | 크롬 내일 만나자 |

첫 번째 사례는 실제 발화 의도가 크롬 실행이었다면 유효한 보정이 될 수 있다.

그러나 두 번째 사례에서는 정상적인 일상 대화가 불필요하게 변경되었다.

이는 문자열 유사도만으로는 사용자의 문맥과 의도를 판단하기 어렵다는 것을 보여준다.

## 13. 조사 손실이 명령어 분석에 미치는 영향

조사 삭제가 단순한 문자 오류율 증가에 그치는지, 실제 명령어 분석에도 영향을 주는지 확인하기 위해 추가 실험을 진행하였다.

### 13.1 파일 열기 명령

입력:

바탕화면에 있는 사진 열어줘

분석 결과:

```python
{
    "type": "open_file",
    "name": "사진",
    "folder": "desktop"
}
```

조사 삭제 이후 입력:

바탕화면 있는 사진 열어줘

분석 결과:

```python
{
    "type": "open_file",
    "name": "바탕화면 있는 사진",
    "folder": ""
}
```

조사가 삭제되면서 기존 정규표현식이 폴더 정보를 인식하지 못하였으며, 파일명 역시 잘못 추출되었다.

### 13.2 일상 대화

메모장이 어디 있더라와 메모장 어디 있더라는 모두 unknown으로 분류되었다.

따라서 해당 사례에서는 조사 삭제가 명령 유형에 영향을 미치지 않았다.

### 13.3 웹 검색 명령

인공지능이 미래 사회에 미치는 영향 검색해줘와 인공지능 미래 사회에 미치는 영향 검색해줘는 모두 웹 검색 명령으로 분류되었다.

그러나 추출된 검색어에는 차이가 발생하였다.

실제 검색 결과의 품질에 미치는 영향은 별도로 측정하지 않았다.

### 13.4 분석 결과

모든 조사가 PC 제어에 반드시 필요한 것은 아니지만, 현재 명령어 분석기에서는 일부 조사가 폴더명과 파일명을 구분하는 중요한 역할을 수행한다.

따라서 다음 두 가지 개선 방향을 고려할 수 있다.

- 오류 보정 단계에서 정상적인 조사 결합 형태를 보호한다.
- 명령어 분석 단계에서 자연스러운 조사 생략 표현도 처리할 수 있도록 개선한다.

본 실험에서는 두 개선 방향의 필요성을 확인하였으며, 별도의 조사 보호 알고리즘을 구현하거나 성능을 측정하지는 않았다.

## 14. 명령어 분석 평가 데이터 구축

음성 인식 정확도의 개선이 실제 명령어 분석 정확도 향상으로 이어지는지 확인하기 위해 기존 음성 데이터에 명령어 정답 정보를 추가하였다.

정답 데이터는 dataset/command_labels.csv에 별도로 저장하였다.

| 명령 유형                 | 데이터 수 |
| ------------------------- | --------: |
| 프로그램 실행             |         9 |
| 웹 검색                   |         7 |
| 파일 열기                 |         6 |
| 실행하지 않아야 하는 발화 |         8 |
| 합계                      |        30 |

정답 데이터에는 명령 유형, 프로그램명, 검색어, 파일명 및 폴더 정보를 포함하였다.

간접적인 실행 요청도 음성 비서가 처리해야 하는 명령으로 정의하였다.

반면 부정 명령, 무음, 일상 대화 및 실행 대상이 없는 불완전한 명령은 unknown으로 정의하였다.

## 15. 오류 보정에 따른 명령어 분석 성능

### 15.1 기존 명령어 분석 성능

| 평가 지표        |   base |  small |
| ---------------- | -----: | -----: |
| 명령 유형 정확도 | 80.00% | 83.33% |
| 전체 명령 일치율 | 63.33% | 70.00% |
| 잘못된 실행 판단 |    2/8 |    3/8 |

기존 명령어 분석기는 별도로 구성된 32개의 단위 테스트를 모두 통과하였다.

그러나 실제 음성 인식 결과를 활용한 평가에서는 다양한 표현, 부정 명령 및 불완전한 명령을 처리하지 못하는 문제가 확인되었다.

### 15.2 오류 보정 적용 결과

| 보정 방식 | 임계값 | base 전체 명령 일치율 | small 전체 명령 일치율 |
| --------- | -----: | --------------------: | ---------------------: |
| 미적용    |      - |                63.33% |                 70.00% |
| 문자      |    0.6 |                63.33% |                 66.67% |
| 문자      |    0.8 |                60.00% |                 60.00% |
| 문자      |    0.9 |                63.33% |                 70.00% |
| 자모      |    0.6 |                63.33% |                 66.67% |
| 자모      |    0.8 |                63.33% |                 66.67% |
| 자모      |    0.9 |                66.67% |                 73.33% |

명령어 분석 평가에서는 대표 임계값인 0.6, 0.8, 0.9를 사용하였다.

총 2개 모델에 각각 7개 조건을 적용하여 420회의 명령어 분석을 수행하였다.

### 15.3 결과 분석

자모 기반 보정과 임계값 0.9를 적용한 경우 두 모델 모두 전체 명령 일치율이 약 3.33%p 증가하였다.

- base: 19/30 → 20/30
- small: 21/30 → 22/30

그러나 음성 인식 정확도에 비해 전체 명령 일치율은 여전히 낮게 나타났다.

이는 음성 인식 오류뿐만 아니라 명령어 분석 알고리즘 자체의 개선이 필요하다는 것을 보여준다.

## 16. 명령어 분석기의 추가 문제 발견

실험 과정에서 다음과 같은 문제를 확인하였다.

| 입력 사례                   | 문제점                                 |
| --------------------------- | -------------------------------------- |
| 나 계산기 쓰고 싶어         | 간접적인 실행 요청 인식 실패           |
| 인터넷 좀 하고 싶어         | 프로그램 실행 의도 인식 실패           |
| 내일 서울 날씨 알아봐줘     | 검색어에 불필요한 '줘'가 포함됨        |
| 계산기 켜지 마              | 부정 명령을 실행 명령으로 분류         |
| 열어줘                      | 실행 대상이 없는데 파일 열기로 분류    |
| 테스트 파일을 찾아서 열어줘 | 파일명 추출 오류                       |
| 무음 데이터                 | 음성 인식 환각으로 인한 검색 명령 생성 |

특히 부정 명령을 실행 명령으로 분류하는 문제는 사용자 의도와 반대되는 동작으로 이어질 수 있으므로 안전성 측면에서 중요하다.

본 실험에서는 실제 PC 제어를 수행하지 않고 명령어 분석 결과만 평가하였다.

따라서 잘못된 실행 판단 건수는 실제 프로그램의 오작동 횟수를 의미하지 않는다.

## 17. 연구 가설 검토

| 가설 | 판단            | 근거                                                               |
| ---- | --------------- | ------------------------------------------------------------------ |
| H1   | 지지            | 자모 단위의 부분적인 문자 차이를 반영함                            |
| H2   | 부분적으로 지지 | 임계값 0.9에서 성능이 향상되었으나 낮은 임계값에서는 성능이 저하됨 |
| H3   | 지지            | 낮은 임계값에서 과잉 보정이 증가하는 경향을 확인함                 |
| H4   | 부분적으로 지지 | 두 모델에서 전체 명령 일치율이 증가하였으나 개선 폭이 제한적임     |

가설에 대한 판단은 현재 개발용 데이터셋에서 관찰된 결과를 바탕으로 하며, 통계적 유의성을 검증한 결과는 아니다.

## 18. 실험의 한계

첫째, 전체 데이터가 30개이며 한 명의 화자가 녹음한 데이터이므로 다양한 발음과 음성 환경에 대한 일반화 성능을 확인하기 어렵다.

둘째, 동일한 데이터셋을 알고리즘 개발과 임계값 비교에 사용하였다. 따라서 임계값 0.9를 독립적인 데이터에서도 최적이라고 단정할 수 없다.

셋째, 보정용 어휘 사전에 실험 데이터에 등장하는 단어가 포함되어 있으므로 특정 데이터에 유리한 결과가 나타날 가능성이 있다.

넷째, 공백 단위로 단어를 분리하기 때문에 조사, 문장부호 및 복합어를 충분히 처리하지 못한다.

다섯째, 자모 기반 유사도는 문맥과 의미를 고려하지 않으며 실제 발음 유사도를 직접 모델링하지 않는다.

여섯째, 명령어 분석 평가에서는 정규화된 문자열의 일치 여부를 사용하였다. 의미가 동일한 다른 표현도 오답으로 처리될 수 있다.

일곱째, 실제 PC 제어 성공률과 전체 시스템 응답 시간은 본 실험에서 측정하지 않았다.

여덟째, 임계값 0.9에서 두 모델 모두 한 문장씩 개선되었으므로 성능 향상의 규모가 제한적이며 통계적 유의성을 판단하기 어렵다.

## 19. 향후 개선 방향

### 19.1 명령어 분석 알고리즘 개선

다양한 한국어 표현과 간접적인 요청을 처리할 수 있도록 기존 규칙 기반 명령어 분석기를 개선한다.

파일 열기 명령에서는 조사 생략 표현을 처리하고, 검색 명령에서는 불필요한 요청 표현이 검색어에 포함되지 않도록 개선한다.

### 19.2 문맥 기반 오류 보정

향후 필요에 따라 명령 유형 및 실행 대상에 따라 보정 가능한 어휘를 제한하는 방식을 검토한다.

이를 통해 일반적인 대화나 정상적인 검색어가 불필요하게 변경되는 문제를 줄일 수 있을 것으로 기대한다.

### 19.3 VAD 기반 음성 인식 개선

Voice Activity Detection을 활용하여 실제 음성이 존재하는 구간을 구분하고, 무음 데이터에서 발생하는 음성 인식 환각을 줄이는 방안을 검토한다.

### 19.4 안전성 개선

부정 명령, 불완전한 명령 및 실행 대상이 존재하지 않는 명령을 실제 PC 제어 이전에 차단할 수 있도록 개선한다.

### 19.5 독립적인 데이터 검증

기존 데이터와 다른 발화 및 화자를 활용하여 오류 보정과 명령어 분석 알고리즘의 일반화 성능을 검증한다.

## 20. 결론

본 실험에서는 Levenshtein Distance를 활용한 일반 문자 기반 오류 보정과 한글 자모 기반 오류 보정 알고리즘을 구현하고 비교하였다.

한글 자모 기반 비교는 완성형 문자 기반 비교보다 부분적인 문자 차이를 세밀하게 반영할 수 있었다.

그러나 낮은 임계값에서는 정상적인 단어와 조사까지 변경하는 과잉 보정 문제가 발생하였으며, 오히려 음성 인식 정확도가 감소하였다.

실험한 조건 중에서는 자모 기반 보정과 임계값 0.9의 조합이 가장 우수한 결과를 나타냈다.

해당 조건에서 base 모델의 음성 인식 완전 일치율은 79.31%, small 모델은 96.55%를 기록하였다.

전체 명령 일치율 역시 base 모델은 66.67%, small 모델은 73.33%로 향상되었다.

다만 개선된 문장은 모델별 한 개에 불과하였으며, 명령어 분석기 자체의 문제와 무음 인식 환각은 해결되지 않았다.

따라서 자모 기반 보정과 임계값 0.9를 후속 실험의 잠정적인 후보 조건으로 선정하되, 실제 시스템 적용 여부는 독립적인 데이터 검증 이후 결정한다.

다음 실험에서는 음성 인식 모델의 추가적인 개선보다 명령어 분석 알고리즘의 구조적 문제를 해결하는 데 집중한다.
