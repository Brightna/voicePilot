# Experiment 02. 문맥 프롬프트를 활용한 한국어 음성 인식 성능 개선

## 1. 연구 배경

VoicePilot은 한국어 음성 명령을 인식하여 프로그램 실행, 웹 검색, 파일 열기 등의 PC 제어 기능을 수행하는 시스템이다.

실험 1에서는 faster-whisper의 tiny, base, small 모델을 대상으로 한국어 음성 인식 정확도와 처리 시간을 비교하였다.

실험 결과, 모델의 크기가 증가할수록 음성 인식 정확도가 높아지는 경향을 확인하였다. 그러나 프로그램 이름, 폴더 이름, 기술 관련 용어 등에서 음성 인식 오류가 발생하였다.

대표적인 오류 사례는 다음과 같다.

- 크롬 → 그럼
- 메모장 → 메모짱
- 인공지능 → 인공지는
- 파이썬 → 파이선

일반적인 음성 인식 시스템과 달리 VoicePilot은 특정 프로그램 이름과 명령어를 반복적으로 사용하는 특성이 있다.

따라서 음성 인식 모델에 PC 제어와 관련된 문맥 정보를 사전에 제공하면, 별도의 모델 학습 없이도 음성 인식 정확도를 개선할 수 있을 것으로 판단하였다.

## 2. 연구 목적

Whisper의 initial_prompt 기능을 활용하여 PC 제어 관련 어휘를 사전에 제공하고, 이에 따른 한국어 음성 인식 성능 변화를 분석한다.

구체적인 연구 목적은 다음과 같다.

- 문맥 프롬프트 적용 전후의 음성 인식 정확도 비교
- 모델 크기에 따른 프롬프트 효과 분석
- 프롬프트 적용에 따른 처리 시간 변화 분석
- 무음 및 비명령 발화에서 발생하는 부작용 확인
- VoicePilot에 적합한 음성 인식 방식 탐색

## 3. 이론적 배경

### 3.1 Whisper의 음성 인식 방식

Whisper는 Transformer 기반의 인코더-디코더 구조를 사용하는 음성 인식 모델이다.

인코더는 입력 음성의 특징을 추출하고, 디코더는 추출된 음성 특징과 이전에 생성된 토큰 등의 문맥 정보를 활용하여 텍스트를 생성한다.

따라서 음성 신호뿐만 아니라 디코더에 제공되는 문맥 정보도 최종 음성 인식 결과에 영향을 줄 수 있다.

### 3.2 Initial Prompt

faster-whisper에서 제공하는 initial_prompt는 음성 인식 과정에서 초기 문맥을 제공하는 기능이다.

특정 분야의 전문 용어, 고유명사 또는 자주 사용되는 단어를 프롬프트에 포함하여 해당 어휘가 인식될 가능성을 높일 수 있다.

본 연구에서는 PC 제어에 자주 사용되는 프로그램 이름, 폴더 이름 및 동작 관련 어휘를 프롬프트로 제공하였다.

이는 모델의 가중치를 변경하는 파인튜닝과 달리 추론 단계에서 문맥 정보를 추가하는 방식이다.

### 3.3 문맥 프롬프트의 한계

Initial Prompt는 특정 단어의 출력을 강제하거나 음성 인식 오류를 반드시 수정하는 기능은 아니다.

프롬프트가 실제 음성보다 과도하게 영향을 미칠 경우, 발화하지 않은 단어가 생성되는 환각 현상이나 반복 출력이 발생할 가능성이 있다.

따라서 정확도뿐만 아니라 오인식 및 오작동 가능성도 함께 분석해야 한다.

## 4. 연구 가설

### 가설 1

PC 제어 관련 어휘를 initial_prompt로 제공하면 프롬프트를 사용하지 않았을 때보다 음성 인식 정확도가 향상될 것이다.

### 가설 2

문맥 프롬프트의 효과는 모델 크기에 따라 다르게 나타날 것이다.

### 가설 3

프롬프트 적용에 따라 음성 인식 처리 시간이 달라질 수 있다.

### 가설 4

문맥 프롬프트는 무음 또는 비명령 발화에서 실제로 발화하지 않은 단어를 생성하는 부작용을 발생시킬 수 있다.

## 6. 실험 설계

### 6.1 독립 변수

- Initial Prompt 적용 여부
- Whisper 모델 크기(tiny, base, small)

### 6.2 종속 변수

- 완전 일치율(Exact Match Accuracy)
- 문자 오류율(Character Error Rate, CER)
- 평균 처리 시간
- 중앙값 처리 시간
- 최대 처리 시간
- 무음 입력에 대한 텍스트 생성 여부

### 6.3 통제 변수

- 동일한 음성 데이터셋
- 동일한 음성 전처리 방식
- 동일한 하드웨어
- 동일한 연산 정밀도
- 동일한 인식 언어
- 동일한 Beam Size

프롬프트 적용 여부에 따른 성능 차이를 비교하기 위해 실험 1에서 사용한 음성 데이터셋과 모델 설정을 유지하였다.

다만 운영체제의 백그라운드 작업 및 순간적인 CPU 사용량까지 완전히 통제하지는 못하였다.

### 6.4 프롬프트 구성

본 실험에서 사용한 프롬프트는 다음과 같다.

계산기, 크롬, 메모장, 파일 탐색기, 바탕화면, 다운로드, 문서, 실행, 검색

프롬프트는 다음 세 가지 유형의 어휘로 구성하였다.

| 유형                | 포함 어휘                         |
| ------------------- | --------------------------------- |
| 프로그램 이름       | 계산기, 크롬, 메모장, 파일 탐색기 |
| 파일 탐색 관련 어휘 | 바탕화면, 다운로드, 문서          |
| 명령 동작 관련 어휘 | 실행, 검색                        |

특정 정답 문장 전체를 프롬프트로 제공하는 대신 PC 제어 환경에서 자주 사용되는 핵심 어휘를 제공하였다.

### 6.5 실험 절차

1. 실험 1의 음성 데이터셋 30개를 불러온다.
2. tiny, base, small 모델을 각각 CPU INT8 환경에서 실행한다.
3. 음성 인식 과정에 동일한 initial_prompt를 적용한다.
4. 각 모델에서 30개의 음성 파일을 인식한다.
5. 인식 결과와 처리 시간을 CSV 파일에 저장한다.
6. 완전 일치율 및 문자 오류율을 계산한다.
7. 실험 1의 프롬프트 미적용 결과와 비교한다.
8. 무음 입력 및 주요 오류 사례를 분석한다.

프롬프트 적용 조건에서 총 90회의 음성 인식을 수행하였다.

실험 1의 결과 90건을 포함하여 총 180건의 인식 결과를 비교하였다.

## 7. 평가 지표

### 7.1 완전 일치율

정답 문장과 음성 인식 결과가 정규화 이후 완전히 일치하는 비율이다.

완전 일치율(%) = 완전히 일치한 문장 수 / 전체 평가 문장 수 × 100

공백과 문장부호는 제거한 후 비교하였다.

무음 데이터 1개를 제외한 29개의 발화 데이터를 평가 대상으로 사용하였다.

### 7.2 문자 오류율(CER)

정답 문장을 인식 결과로 변환하기 위해 필요한 문자 삽입, 삭제, 치환 횟수를 기반으로 오류율을 계산한다.

CER(%) = (삽입 + 삭제 + 치환 오류의 합) / 전체 정답 문자 수 × 100

본 실험에서는 한글 음절 단위의 편집 거리를 사용하였다.

전체 발화의 오류 문자 수와 정답 문자 수를 합산하여 CER을 계산하였다.

### 7.3 처리 시간

Python의 time.perf_counter()를 사용하여 음성 인식 시작부터 최종 텍스트 생성까지 소요된 시간을 측정하였다.

모델 로딩 시간과 음성 파일 읽기 시간은 측정에서 제외하였다.

처리 시간 통계에는 무음 데이터를 포함한 30개의 데이터를 사용하였다.

따라서 측정 결과는 실제 사용자 발화 시작부터 PC 제어 완료까지의 전체 응답 시간이 아닌 음성 인식 처리 시간이다.

## 8. 실험 결과

### 8.1 완전 일치율 비교

| 모델  | 프롬프트 미적용 |  프롬프트 적용 |   변화량 |
| ----- | --------------: | -------------: | -------: |
| tiny  |  37.93% (11/29) | 58.62% (17/29) | +20.69%p |
| base  |  58.62% (17/29) | 75.86% (22/29) | +17.24%p |
| small |  79.31% (23/29) | 93.10% (27/29) | +13.79%p |

모든 모델에서 프롬프트 적용 이후 완전 일치율이 증가하였다.

tiny 모델에서 가장 큰 완전 일치율 증가 폭이 나타났으며, small 모델은 프롬프트 적용 이후 가장 높은 완전 일치율을 기록하였다.

### 8.2 문자 오류율 비교

| 모델  | 프롬프트 미적용 | 프롬프트 적용 |  변화량 |
| ----- | --------------: | ------------: | ------: |
| tiny  |          16.23% |        17.74% | +1.51%p |
| base  |           9.43% |         7.92% | -1.51%p |
| small |           3.02% |         0.75% | -2.27%p |

base와 small 모델에서는 문자 오류율이 감소하였다.

특히 small 모델은 기존 3.02%에서 0.75%로 감소하여 약 75.2%의 상대적인 오류율 감소를 기록하였다.

반면 tiny 모델은 완전 일치율이 증가했음에도 문자 오류율이 증가하였다.

이는 일부 문장에서 발생한 반복 출력 및 과도한 문자 삽입 오류가 전체 문자 오류율에 영향을 미쳤기 때문이다.

따라서 완전 일치율과 문자 오류율을 함께 고려해야 한다.

### 8.3 평균 처리 시간 비교

모든 모델에서 프롬프트 적용 조건의 평균 처리 시간이 증가하였다.

다만 각 조건에서 반복 측정을 수행하지 않았으며 시스템 부하를 완전히 통제하지 못하였으므로, 처리 시간 증가의 원인을 프롬프트 적용만으로 단정할 수 없다.

small 모델의 경우 평균 및 중앙값 처리 시간이 증가했지만 최대 처리 시간은 감소하였다.

이는 일부 발화에서 발생한 긴 처리 시간이 프롬프트 적용 조건에서 줄어들었음을 보여준다.

그러나 단일 측정 결과이므로 응답 시간의 안정성이 향상되었다고 일반화하기는 어렵다.

## 9. 주요 음성 인식 사례 분석

### 9.1 프로그램 이름 인식 개선

정답: 크롬 실행해 줘

프롬프트 미적용 조건에서는 세 모델 모두 크롬을 그럼으로 잘못 인식하였다.

base 모델에 프롬프트를 적용한 결과 다음과 같이 인식하였다.

- 적용 전: 그럼 실행해줘
- 적용 후: 크롬, 실행 해줘

공백과 문장부호를 제거하면 정답과 완전히 일치한다.

PC 제어 시스템에서 프로그램 이름은 실제 실행 대상을 결정하는 핵심 정보이므로, 이러한 오류 개선은 명령 수행 정확도 향상에 기여할 가능성이 있다.

다만 실제 명령 실행 성공률은 본 실험에서 별도로 측정하지 않았다.

### 9.2 파일 탐색 관련 어휘 개선

정답: 다운로드 폴더에 있는 보고서 열어 줘

base 모델의 프롬프트 미적용 결과는 다음과 같다.

다음 로드 폴더에 있는 보고서 열어줘

프롬프트 적용 이후 해당 문장을 정확하게 인식하였다.

이를 통해 프로그램 이름뿐만 아니라 파일 탐색에 사용되는 폴더 이름에서도 문맥 프롬프트가 도움이 될 수 있음을 확인하였다.

### 9.3 프롬프트 적용 이후에도 남은 오류

small 모델의 프롬프트 적용 조건에서는 29개 발화 중 27개가 정답과 완전히 일치하였다.

남은 두 오류는 다음과 같다.

| 정답 어휘 | 인식 결과 |
| --------- | --------- |
| 인공지능  | 인공지는  |
| 파이썬    | 파이선    |

두 오류 모두 한글 음절 한 글자가 치환된 사례이다.

이는 프롬프트만으로 모든 한국어 음성 인식 오류를 해결할 수 없으며, 한글의 구조적 특성을 활용한 후처리 방식이 추가적인 개선 가능성을 가질 수 있음을 보여준다.

## 10. 프롬프트 적용의 부작용

### 10.1 무음 입력에서의 환각 현상

무음 데이터에 대한 음성 인식 결과는 다음과 같다.

| 모델  | 프롬프트 미적용 | 프롬프트 적용                        |
| ----- | --------------- | ------------------------------------ |
| tiny  | 빈 문자열       | 빈 문자열                            |
| base  | 빈 문자열       | 빈 문자열                            |
| small | 빈 문자열       | 다운로드, 다운로드, 문서, 실행, 검색 |

small 모델에서 실제 발화가 존재하지 않음에도 프롬프트에 포함된 단어들이 출력되었다.

이는 문맥 프롬프트가 음성 정보가 부족한 상황에서 부적절한 텍스트 생성을 유발할 수 있음을 보여주는 사례이다.

특히 VoicePilot은 음성 인식 결과를 실제 PC 제어 명령으로 연결하기 때문에 이러한 환각 현상은 중요한 안전성 문제로 이어질 수 있다.

다만 본 실험에서는 실제 명령 실행 여부를 평가하지 않았으므로 오작동이 발생했다고 단정할 수는 없다.

### 10.2 반복 출력

base 모델에서는 다음과 같은 반복 출력이 관찰되었다.

- 정답: 오늘 너무 피곤하다
- 인식 결과: 오늘 너무 피곤하다 오늘 오늘 너무 피곤하다

또한 tiny 모델에서는 짧은 발화가 긴 숫자 문자열로 잘못 인식되는 사례가 나타났다.

이러한 삽입 오류는 완전 일치율이 향상되더라도 전체 문자 오류율을 증가시킬 수 있다.

### 10.3 대응 방안

향후 다음과 같은 개선 방법을 검토한다.

- VAD를 활용한 무음 구간 및 실제 발화 감지
- 명령어 분석 단계에서의 유효성 검사
- 불완전한 명령어 및 부정 명령어의 실행 방지
- 한글 자모 기반 오류 보정
- 과도한 오류 보정을 방지하기 위한 유사도 임계값 설정

## 11. 모델별 종합 분석

### 11.1 tiny 모델

완전 일치율은 크게 향상되었지만 문자 오류율은 오히려 증가하였다.

처리 속도는 가장 빠르지만 일부 발화에서 과도한 오류가 발생하므로 안정적인 PC 제어에 활용하기 위해서는 추가적인 검증이 필요하다.

### 11.2 base 모델

프롬프트 적용 이후 완전 일치율과 문자 오류율이 모두 개선되었다.

평균 처리 시간은 약 1.48초로, 정확도와 처리 속도의 균형을 고려할 때 활용 가능성이 있는 모델이다.

### 11.3 small 모델

프롬프트 적용 이후 완전 일치율 93.10%, 문자 오류율 0.75%로 가장 우수한 음성 인식 정확도를 기록하였다.

그러나 평균 처리 시간이 약 3.71초로 상대적으로 길고, 무음 입력에서 환각 현상이 발생하였다.

### 11.4 base와 small 모델 비교

프롬프트를 적용한 base 모델과 small 모델의 성능을 비교하면 다음과 같다.

| 지표           |     base |    small |
| -------------- | -------: | -------: |
| 완전 일치율    |   75.86% |   93.10% |
| 문자 오류율    |    7.92% |    0.75% |
| 평균 처리 시간 | 1.4827초 | 3.7141초 |
| 무음 환각 관찰 |     없음 |     있음 |

small 모델은 base 모델보다 문자 오류율이 약 90.5% 낮지만, 평균 처리 시간이 약 2.23초 더 길다.

VoicePilot에서는 빠른 응답뿐만 아니라 정확한 실행 대상 인식과 오작동 방지도 중요하다.

따라서 본 실험에서는 최종 모델을 확정하지 않고 base와 small 모델을 후속 연구 대상으로 유지한다.

## 12. 연구 가설 검토

| 가설                                     | 실험 결과                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| 프롬프트 적용 시 정확도가 향상될 것이다. | 부분적으로 지지됨. 모든 모델의 완전 일치율이 향상되었으나 tiny의 CER은 증가함. |
| 모델 크기에 따라 효과가 다를 것이다.     | 모델별 정확도 변화 양상이 다르게 관찰됨.                                       |
| 처리 시간이 달라질 수 있다.              | 모든 모델에서 평균 처리 시간 증가가 관찰됨. 인과관계는 추가 검증 필요.         |
| 환각 현상이 발생할 수 있다.              | small 모델의 무음 입력에서 관찰됨.                                             |

본 실험은 제한된 데이터셋을 활용한 탐색적 실험이므로 통계적 유의성을 검증한 결과는 아니다.

## 13. 연구의 한계

첫째, 전체 데이터셋이 30개의 음성 파일로 구성되어 있어 데이터 규모가 제한적이다.

둘째, 단일 화자의 음성을 사용하였으므로 다른 사용자의 발음, 억양 및 말하기 속도에서도 동일한 결과가 나타나는지 확인하지 못하였다.

셋째, 하나의 고정된 프롬프트만 사용하였으므로 프롬프트의 길이, 어휘 순서 및 구성에 따른 효과는 분석하지 못하였다.

넷째, 각 조건에서 반복 측정을 수행하지 않아 처리 시간의 변동성과 재현성을 충분히 평가하지 못하였다.

다섯째, 무음 데이터가 한 개뿐이므로 환각 발생률을 일반화할 수 없다.

여섯째, 음성 인식 정확도를 중심으로 평가하였으며 실제 명령 분류 정확도 및 PC 제어 성공률은 측정하지 않았다.

일곱째, 기존 개발 데이터셋을 활용하였으므로 새로운 발화에 대한 일반화 성능을 별도의 데이터셋에서 검증해야 한다.

## 14. 결론

본 연구에서는 faster-whisper의 initial_prompt 기능을 활용하여 PC 제어 관련 문맥 정보를 제공하고 한국어 음성 인식 성능 변화를 분석하였다.

실험 결과, 모든 모델에서 완전 일치율이 향상되었으며 base와 small 모델에서는 문자 오류율도 감소하였다.

특히 small 모델은 완전 일치율 93.10%, 문자 오류율 0.75%를 기록하여 별도의 모델 재학습 없이 문맥 정보를 제공하는 방식이 음성 인식 성능 개선에 활용될 가능성을 보여주었다.

반면 평균 처리 시간 증가, 반복 출력 및 무음 입력에서의 환각 현상도 관찰되었다.

따라서 문맥 프롬프트는 음성 인식 정확도를 개선하기 위한 효과적인 후보 기술이지만, 실제 PC 제어 시스템에 적용하기 위해서는 추가적인 안전성 검증과 오류 보정이 필요하다.

## 15. 후속 연구 방향

다음 실험에서는 한국어 음성 인식 과정에서 발생하는 유사 발음 오류를 개선하기 위해 한글 자모 기반 오류 보정 방식을 연구한다.

일반 문자 기반 편집 거리와 한글 자모 기반 편집 거리를 비교하여 한국어 명령어 인식에 적합한 보정 방식을 탐색한다.

이후 명령어 분류 정확도, VAD 기반 녹음 방식, 오작동 방지 및 전체 시스템 응답 시간을 평가하여 최종 음성 인식 모델과 처리 구조를 결정할 예정이다.
